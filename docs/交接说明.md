## 未完成任务：零件音频的语调问题 ⚠️

### 现象

用户报告：游戏里开自动驾驶听到的是「**自动驾驶，启动**」，听感生硬。

### 已查明的事实

**1. 这是 X4 的「积木式」拼接机制**，不是 bug。飞船电脑语音由两类零件顺序播放拼成：

- **名词零件**：`441=自动驾驶`、`440=跳跃驱动器`、`439=护盾增强`、`438=助推器`、`443=弹射座椅`、`444=覆盖系统`、`442=洗碗机`、`432=扫描`、`433=长距扫描`、`434=标记`、`436=骇入`、`437=隐秘`、`430=模式`、`431=自毁`、`435=标记小行星`
- **状态零件**：`400=已激活。`、`401=已启动。`、`402=已启用。`、`403=启动。`、`405=已停用。`、`406=已禁用。`、`407=已脱离。`、`408=已中断。`、`409=完成。`、`410=已完成。`、`411=成功。`、`412=被阻止。`、`413=失败。`、`414=极其失败。`、`415=已爆炸。`

⇒ `441` + `403` = 「自动驾驶，启动」

**2. 拼接关系是引擎硬编码的，找不到配置表。** 已排查：
- `md/`（332 个）+ `aiscripts/`（184 个）脚本：只有 3 个文件引用 `page="10002"`，且都是 `<text>`（显示文本）不是 `<speak>`（语音）
- `libraries/`（132 个 xml）：无 cue 定义表
- `libraries/voicesequences.xml`：64 条序列、20 个 page，**不含 441/403**，只管 gamestart/剧情场景

**3. 指令与标点都改不了词组的收尾降调。** 实测「自动驾驶」的基频末段：

| 尝试 | 结尾相对起点 |
|---|---|
| 原样 `自动驾驶` | **−34.2%** |
| 加逗号 `自动驾驶，` | −36.4% |
| 指令「词组、中性、别下沉」 | −31.0% |
| 指令「前半部分、轻微上扬」 | −33.3% |

⇒ TTS 对孤立词组的降调是**固有行为**，靠 prompt 和标点都拧不过来。

### 用户提的两个方案（待评估）

> 用户原话：「如果零件音频在游戏内被使用的次数不多，干脆我们直接搞成一整段，或者拿一整段音频裁剪成零件」

**方案 A · 整段替换**：把 `441` 的音频录成整句、`403` 录成静音 ⇒ 拼接后 = 整句。
**方案 B · 整段裁剪成零件**：合成整句「自动驾驶，启动」，在「启动」处裁开，前半填 `441`、后半填 `403`。

**两个方案的共同前提**：`441` 与 `403` 的**配对必须固定**。
若 `441` 也跟 `405`/`400`/其他状态零件组合，针对单一组合优化会破坏其他组合。

### 下一步该做的（新会话从这里开始）

**第一件事：确定前置零件的实际配对数量。** 这是决定方案的唯一未知数。可选路径：

1. **实测法**（最可靠）：把 `441` 的音频临时换成一段**独特标记音**（如口哨），`400`–`415` 各换成不同的可辨识短音，
   进游戏反复触发各类飞船操作，录下实际组合。代价是要玩一会儿，但能拿到确凿的配对表。
2. **文本侧推断**：`t/0001-l086.xml` 里同 page 的文本 id 命名与邻近关系，可能暗示哪些是成对使用的；
   但语音调用不走 t 文件，只能作旁证。
3. **X4.exe 内存/字符串分析**：拼接表若硬编码在引擎里，可能在 exe 的数据段。至今只做过字符串层扫描，未深挖。

**若配对固定** → 用方案 B（整段裁剪），效果最好：语调连贯、无拼接感。
**若配对多对多** → 退回「零件化但更自然」的路线，可尝试：
- 把名词零件的**语速调更慢、尾音拖长**（弱化降调的存在感）

## 关键技术坑（务必先读，全都踩过）

1. **语音替换必须走 `sound_library` 重定向，不能覆盖同名文件。**
   实测：往扩展里放 `voice-l044/...` 同名覆盖**无效**（覆盖机制对脚本/贴图/UI 有效，对音频这条查找路径无效）。
   重定向到一个**只存在于扩展里的新路径**才行。
2. **两代音色必须用不同的 `X-Api-Resource-Id`。** 1.0 → `seed-tts-1.0`，2.0 → `seed-tts-2.0`。
   用 `volc.service_type.10029` 调 1.0 音色**能出声**，但 `context_texts` 会被**静默忽略**（时长与基频和"无指令"版完全一致，极易误判为"这音色不吃指令"）。
3. **语气指令走 `additions.context_texts` 参数，不能拼进正文。** 文档里的 `[#...]` 是**控制台试听界面**的写法，拼进 `text` 会被当正文念出来。
4. **`content.xml` 里未转义的 `&` 会让 X4 静默丢弃整个扩展**（扩展列表里根本看不到）。构建器已用 `quoteattr()` + `ElementTree` 自检。
5. **`Documents\Egosoft\X4\<steamid>\content.xml` 是扩展启用表**，只有 `enabled="true"` 才加载。当前 `x4_annc_cn` 已登记为 true（备份 `content.xml.bak-before-annc`）。
6. **`.cat` 必须是 LF 行尾**，已在 `.gitattributes` 里钉死（`*.cat -text`）。
7. **火山 TTS 输出自带约 174ms 首静音 + 500ms 尾静音**。完整句只是浪费，拼接时叠加成 685ms 空白，听感灾难。构建器 `trim_silence()` 已自动裁到 30ms/60ms。
8. **临时文件别放 `%TEMP%`**：跨盘 `os.replace` 会报 `WinError 17`，要在目标同目录建临时文件。
9. **文件名不能含 `/`**（合成样例命名时踩过）。
10. **`load_all(game, [...])` 的第二个参数筛的是归档名（03 / ego_dlc_boron），不是语言**，语言要在 `VOICE_RE` 匹配后自己筛。
